# learnings/building

Build and slicing-tool learnings for the 3dp project, moved unchanged from learnings.building (2026-10-07); design and picture learnings are in learnings/design.

> * Mesh reading (2026-09-30): before naming a feature, measure its extent, count and spacing, and cut both a top-down slice and a side section through it. insert_rev3's four 1.5 mm ceiling features were first read as variant pips, then as ribs. A top-down slice showed they were raised tubes around Ø 4 mm holes. Both wrong readings were saved to the product doc and had to be corrected.  
> * Orientation check (2026-09-30): on the wire shelf, printing on its side put the crosswire slot width in X-Y but the keyhole neck width in Z, where 0.1 mm test steps can't work; this was first missed.  
> * Claude builds watertight meshes with its own numpy/scipy code and writes Orca 3mfs directly, with settings, height ranges, seam paint and custom G-code (nurseryPots_lib.py, 2026-09-30). Earlier parts were STLs made of convex solids. It can't engrave text, so parts are labeled with ribs or raised pips (pip count = variant number).  
> * Slicing in the workspace: check a 3mf with the command-line slicer before sending it (build-3dp, Slicing). The Orca version must match the one that saved the file; an older version refuses newer files. The command-line slicer drops layer-slider custom G-code (the pots' fan ramp is missing even from the original files); use the Layer change G-code workaround in learnings/speed-and-cooling (Changing temperature for part of a print), or check it in the Orca preview (2026-09-30).  
> * Tool notes (2026-09-30): Claude reads an attached 3mf fully: every setting, the height ranges, custom G-code and the mesh. A 3mf doesn't show whether a setting was saved to a preset or edited only in that project. It does name its presets (printer_settings_id, print_settings_id) and, for a user preset, the system preset it builds on (inherits_group) and every setting changed from it (different_settings_to_system); a "defaults" file sent 2026-10-10 held my "0.6mm default" preset, 15 changes from stock. orcadefaults.py --diff lists a file's changes from my default settings. Large meshes (insert_rev3: 145 MB, 945,000 vertices) are analyzed with Claude's own numpy plane cuts (top-down slices and side sections), which take under a minute (2026-09-30).  
> * Orca's own files (2026-10-02): its system profiles and calibration models are inside the extracted AppImage (resources/profiles/BBL and resources/calib). The calibration models are Draco (.drc) meshes, which the command-line slicer opens; --export-stls writes them out as STLs.  
> * Orca's calibration test files (2026-10-02): the PA Pattern's 3mf holds only a 25.6 mm placeholder box, because the GUI generates the pattern when it slices, so read the sliced .gcode.3mf instead.  
> * Multi-color parts (2026-10-02, calibration rig rev1.1): each color is its own part with its own "extruder" value in the 3mf's model_settings.config, built from separate closed boxes with touching faces inset 0.005 mm; Orca's 0.049 mm slice gap closing joins them. The sliced black paths decoded as the intended markers (IDs 0, 1 and 27).  
> * Settings bases (2026-10-03): one settings base can serve several build scripts (rfidSpring_settings_base.json: rfid rev1 and rev2, calibration-rig rev1.1). Never overwrite a base; save a changed one under a new name and point the new script at it.  
> * Orca's excluded-area check (2026-10-03, calibration rig rev1): Orca tests an object's convex outline, not its actual shape, against the printer's excluded corner, so a notch smaller than the outline's bridge still fails ("too close to exclusion area", return code -64 from the command-line slicer). Clear the corner with the whole outline, for example by shortening the part, and test it with the command-line slicer before settling a design.  
> * Toolpath fill check (2026-10-03): drawing each layer's extrusions at their real width and comparing them with the design shows unfilled spots before printing. For rev1.1's single black layer it predicted the white specks the photos showed.  
> * Float slivers (2026-10-03): split rectangles at coordinates rounded to 6 decimals, or float error leaves pieces about 0.01 mm wide (rev1 had 23).  
> * Pricing a setting change (2026-10-03): re-slice a copy of the 3mf with only that setting changed, using the command-line slicer, and compare Orca's estimates. The photo board audit priced 8 options this way.  
> * Bambu color codes (2026-10-03): Orca's resources/profiles/BBL/filament/filaments_color_codes.json lists the hex code for every Bambu filament color. Set filament_colour in the 3mf to the right code so the AMS matches the right spool: PLA Matte Ivory White #FFFFFF, Bone White #CBC6B8, Charcoal #000000.  
> * Orca's stock "Bambu PETG Translucent @BBL X1C 0.8 nozzle" (Listed, Orca 2.4.2 profile files; listed for the P1S 0.6 nozzle): 245 °C (250 first layer), 16 mm³/s, part fan 20–60%, flow 0.95, 0.2 mm retraction (2026-10-01).  
> * Orca command-line slicer, more stubs (2026-10-04): in thread workspaces Orca 2.4.2 also needed stubs for libEGL.so.1, libsoup-3.0.so.0, libwayland-server.so.0 and libsecret-1.so.0. orca-setup.sh stubs every missing library (2026-10-07). Its G-code uses relative extrusion (M83).  
> * Overhang check (2026-10-04, barrinaClip): the sliced layers marked '; FEATURE: Overhang wall' or 'Bridge' showed one-sided notch-roof bridges; a ramp that grows 0.31 mm per 0.3 mm layer (one extrusion per layer) removed them.
> * Reusing a part from a 3mf (2026-10-04, barrinaClip_rev2): sectioning the mesh (parse 3D/Objects/*.model directly; trimesh's 3mf loader and section() need networkx and scipy) and comparing areas with the build script's profile matched to 0.000 mm². A check on the part's solid alone missed a filled hinge slot; the keep-out zone (part, swing room, mouth) had to be checked, voids included.
> * Shapely fills (2026-10-04): a polygon built from four hand-ordered corners can cross itself and make GEOS throw a TopologyException in unary_union; build fills as MultiPoint(points).convex_hull. Count pieces before keeping the largest, or a 'one piece' check always passes.
> * Unchanged rebuilds (2026-10-06, calibration-stand): a sed for build(30,30) missed profs.py's G['build'](30,30), so the 10 deep hinge slots drew unchanged and were reported as done. After changing a model value, test a point or area that must differ from the old model before drawing or reporting it.
> * Corner rounding helper (2026-10-06): rounding the open area in a local box needs the box half-size above 1.5 times the radius, or the trimmed inner box is empty and nothing rounds (the left brace's r6 was missing in one draw).
> * Slicer sensitivity (2026-10-07, rfidSpring_rev2): shifting the whole mesh 0.00002 mm moved Orca's time estimate 8 s (25 min 40 s to 25 min 48 s), and rewriting it with 0.00001 mm rounding differences moved it 21 s, with the same filament weight. Compare G-code only between slices of files with identical vertices; a few seconds' change after a rewrite isn't a design change.
> * Smooth lofts, not stacked slabs (2026-10-08, shelf bore-test-piece_rev2): an outline built as 0.3 mm slabs, each inset for the fillet at its height, gave dpcheck over 1,000 false findings (each step read as a sharp edge, a flush step or an off-grid height). Build rounded and chamfered outlines as a loft through rings of equal point count (loft() in that script).
> * Floating strips pass dpcheck (2026-10-10, shelf): its island check fails only a layer region with nothing under it at all, so front-fit-test_rev1's roof strip, which grew along the sleeve out of a supported region, passed it while OrcaSlicer warned of a floating cantilever, and the print strung. A per-layer difference against the layer below grown by 0.31 mm (one 45° step) found the strip at layer 32 (x 10.5–41.5). dpcheck's islands check does this since 2026-10-11 (calibration-stand: it caught dovetail slot-roof strands the slicer warned of on one block of two).
> * manifold3d meshes (2026-10-08): trimesh's merge_vertices() on manifold3d output left 506 edges shared by four faces (not watertight); build the Trimesh with process=False. A 45-degree teardrop roof runs from the tangent points (r/√2 off center, r/√2 up) to the apex r√2 up; a triangle based on the center line sticks out past the circle (cost a redraw).
> * Filament swap in a settings base (2026-10-08): shelf/build/shelf_settings_base.py resolves an Orca profile's inherits chain and writes it into slot 1 of an existing base. Per-filament arrays hold two entries per filament (Direct Drive Standard, High Flow), so a two-filament base has 4.
- Saved measuring and stats tools (2026-10-09, nursery-pots): projects/3dp/scripts/gcodeStats.py (per-layer feature totals; extrusion runs and short-run counts, arc-aware: a chord-only parser undercounted curved top lines) and meshmeasure.py (ray-cast measuring); nursery-pots/build/insertMeasure.py and insertPicture.py. Check these before writing a parser or measurer.
- Labels and builder inputs (2026-10-09, 2.5in insert): build_insert's slot_r0/slot_r1 are the slot's outer ends, not its end-circle centers (a typed label said r 14.68 for a 14.18 end), and a c>0 edge's Z ends sit at c/√2 and c√2, not c (c = 2.0 left them at 1.41 and 2.83 mm, off the 0.4 mm grid). Label dims from the mesh (insertMeasure.py), never from typed values.
