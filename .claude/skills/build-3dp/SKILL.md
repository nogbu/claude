## Design principles
- Before any 3D-printed design or concept (tests included), and before building or auditing one, read design-principles.md in this folder in full.

## Designing and building
- Print names: a multi-plate file adds the plate number as a third part ("rev9.3.1" is rev9.3 plate 1); a single-plate file uses the rev alone.
- Model check: to check a principle projects/3dp/scripts/dpcheck.py covers (1, 2, 3, 4, 12), run only that check (--only [check or principle number], --near x,y for one spot) on the model file the build script writes, or a scratch copy; report its FAIL and CHECK lines.
- Slicing: slice with /opt/orca/slice [file] [outdir], which ends with each plate's time, layers, height and grams; if it's missing, wait for /tmp/setup-env.done (log /tmp/setup-env.log), and run shared/scripts/setup-env.sh orca yourself if it never appears or the thread isn't in 3dp, instead of the orca-cli-slice skill's steps 2 to 4.
- 3mf files: build scripts write them with projects/3dp/scripts/write3mf.py, never a copied writer; add anything it lacks (e.g. multiple plates) to it.
- My source file: a 3mf or model I made sets its product's layout, parts, text, colors and settings, the same as my own words (CLAUDE.md, Questions: never re-ask what my words settled). Apply agreed changes onto it without changing anything else, and ask only about what the file and the doc leave open. When an agreed change reads differently from the file, follow the file. (plantTags: Claude merged the file's separate name and species tags into one, then asked about colors the file set.) When a 3mf is attached, compare its settings with the product doc and report any difference.
- Reused parts (e.g. the Barrina snap U): read the part's geometry from its file's mesh and check it against its build script; keep it unchanged, slots and gaps included, and design only the material joining it. Before any image, check that the part's zone in the new design matches the file, voids included.
- Geometry claims: check every claim about what a change cuts, splits, clears or thins against the model before sending it.
- Fillets: every proposed curve is tangent to both faces it joins; if that breaks a rule, show the conflict.
- Every scratch folder a product doc names has a run.sh, kept current, that installs its libraries in one pip call, copies in the scripts it needs and saves built files beside it with a fingerprint of those scripts, reusing them when none changed.

## Pictures
- "render it" / "show me": start drawing at once, with a line or two; refine only if I ask. The first picture must let me judge the design: solid shading, every face edge drawn, the smallest designed feature (edge curve, slot, gap) plainly visible, and for a whole design, views from two or more sides plus labeled close-ups of its detailed areas.
- Draw every picture from one working model: the model file the build script writes, updated with each agreed change, saved or not (a scratch copy if there is none yet), drawn with projects/3dp/scripts/render3d.py load, never from a second hand-built model or by eye. Leave dim labels to measure themselves, caption with source(), save with save(), and name in the title any change the model can't show yet.
- Redraw any picture older than the latest agreed change before showing it (audit and earlier-thread pictures included), unless no later change touches what it shows; then say when it was drawn and that nothing since changes it.
- Before sending, check every element against the geometry: cut-off parts run off the frame, markers sit at coordinates, labels match their parts.
- Show a fresh image before a build question, before any card that sets or changes a size, shape or position, or asks which of several shapes my words mean (every option pictured, as Comparing options says), before any card that sets how a part is sized or checked (the part with its loads, their positions and the space it can grow into), and before any message naming something not pictured here; not when re-asking. It follows the model and whole-design rules above; a 2D sketch never stands in for it.
- Comparing options: when a picture or card compares options, draw them in one picture, side by side, each row the same view, crop and scale for every option, with the same example (heights, loads) in each. Every panel shows the part mounted on what holds it, and where the mount is hidden, add a row with the part pulled off, seen from where its hooks or grooves show. Letter each option's panels in their titles (A, B, C and so on), and start each card option's label with the same letter.
- Before the first render, apply the defaults earlier redraws taught: option rows share one frame and scale (render3d.py place(), mossPlank_jointFix_pic.py row()); option pictures start from shelf's rear-sleeve_reach_options.py layout (framed zoom, numbers in a row below the parts, never over them); label only the view that shows each piece's identifying face; keep text inside its own panel; read learnings/design's notes on turned-over parts and coloring a spot before drawing either.
- Explaining geometry: when an answer turns on shape or position (why a part can't move, what a change hits, where a strength check's peaks sit), send a picture with it.
- Attach each picture to its message, never only link it; give a redrawn picture a new file name, and resend a reply whose result shows it unattached; past six pictures, send the rest in follow-up messages before any question. A card about a pictured item comes right after a reply carrying that item's picture. On "where is the picture," send the picture the latest card or message needed, drawing it if it doesn't exist yet; resend an earlier picture only when I name it. A thread takes at most 24 attachments. Past 20, tell me and give pkg step 8's fresh-thread prompt. If an attachment is refused, the zoom page carries the pictures; never send a bare file path.
- Zoom pages (user 2026-10-11): every message that attaches pictures also links a private Artifact page, one per message, made with projects/3dp/scripts/zoompage.py. The page shows each picture at full resolution to zoom and pan, and each pictured part as a 3D model to turn and zoom, colored by stress when a 3D check gave it. Keep attaching the picture files too.
- A picture about one spot opens with a 3D view of the whole design, the spot's own mesh faces colored bright, never covered by a shape laid over them (an added marker may only outline it), and labeled plainly; each close-up sits beside it in that color, tied by a line or label, saying which way it looks.
- Walkthrough pictures: draw each item's picture only when its item comes up, never ahead. Picture scripts check their own layout (clipped or overlapping text) when they save; look at a picture again only when that check flags it.

## Measuring and photos
- Photo confirmation: when it isn't clear what a photo shows or which feature a scale is against, show me an annotated crop and ask, one photo per question, before recording any value from it.
- Measurement photos live in /mnt/project-files/photos/[subject]/, one folder per subject, each indexed by a content file photos.[subject]. Copy each photo I attach from /mnt/project-files/uploads/hearth/ into its folder under the name I gave it (ask if I gave none); read photos from the folder, not earlier chats, and cite the photo's name with every value recorded.

## Troubleshooting
- Troubleshooting prints: find and fix the cause; offer a step that only hides it only when I ask. Before naming suspects, run projects/3dp/scripts/settingsdiff.py on this print's 3mf and a good print's at the same height, and list every difference. Test one change at a time against the last good print, checking the G-code for it first. Save a cause only once a test isolates it; until then it's a suspect.
